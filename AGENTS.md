# AGENTS.md

- The Houcine.tech "What I Use to Build" tools and categories live only in `src/content/techStack.ts` (checked by `scripts/dev/tech-stack.test.mjs`) so the section stays data-driven and core tools stay distinct from per-project ones.
- Houcine.tech services and prices live only in `src/content/techCatalogue.ts`; the server copy `supabase/functions/send-notification/techPrices.ts` must match it (enforced by `scripts/dev/tech-catalogue.test.mjs`) because the edge function cannot import from `src/`.
- Quote budgets are checked twice: the form only offers ranges at or above the service's starting price, and `checkTechBudget` in send-notification refuses anything else, so the client is never the only guard.
- What the AI agents may say lives only in the knowledge brain, `houcine-world-brain/` (Markdown notes, `docs/knowledge-brain.md`). After editing a note, rebuild the index with `node --experimental-strip-types scripts/brain/build.mjs` and commit `supabase/functions/_shared/brain/index.generated.ts`; `scripts/ci/brain.test.mjs` fails if it is stale, if a note is invalid, or if a `fact_` value disagrees with the site's constant. Never write brand facts into prompts or code, and never invent a fact to fill a gap: mark it `> [!incomplete]` or add it to `internal/open-questions.md`.
- Knowledge Studio (`/workspace/knowledge`, `docs/knowledge-studio.md`) edits the same Markdown notes and publishes them with ONE commit to `main` containing the notes, `index.generated.ts` and `knowledge-studio/snapshot.generated.ts`; all three are produced by `supabase/functions/_shared/brain/compile.ts`. Never add a second compiler or a database copy of the knowledge. Every Studio request is checked for a super admin on the server (`knowledge-studio/index.ts`), never only in the page.
